从程序编译器到企业上下文编译器

From Program Compiler to Enterprise Context Compiler

 October 28, 2026  |  476 tokens  |  @HugoSkills  |  hugozhu.site

昨天那篇 每天 1000 条钉钉消息，我让一个 Agent 先编译再开口 是从一个 ❌ 开始的：我在单聊里问一位同事某件事要不要先做，他回了四个字「今天弄好」；5 分钟后，我的工作助理 Muse 把这句话当成急事推给了我——而我 7 分钟前就在和他聊这件事。

那次修的是推送时机。但这四个字之后一直在我脑子里，因为它暴露了另一个问题：同一件事，在我的台账里是「等别人交付」，在他那边是「我要办」。 Muse 只编译了我这一半。他那一半在他脑子里、在他的待办里，或者哪儿都没有。

把一个人的工作流编译成 AI 能用的上下文，444 那篇已经跑通了。这篇往上走一层：一个组织的工作流，能不能像程序一样，被一台编译器编成 AI 可以执行的上下文？

我的回答是能，但前提是把「编译器」这个类比当真——不是借个名字，而是把词法分析、符号表、中间表示、链接、增量编译一一对上，再老实承认它在哪里不成立。恰恰是不成立的那几处，决定了这台编译器该怎么设计。

过去只有富人和大公司买得起的服务，正在变成默认配置

Services Only the Rich and Big Companies Could Buy Are Becoming the Default

 October 23, 2026  |  253 tokens  |  @HugoSkills  |  hugozhu.site

曾鸣第三次「看十年」公开课的整理稿今天上午刚发出来——笔记侠整理，两万多字，讲的是他在杭州湖畔创研中心那场演讲。他开场第一句不是讲趋势，是讲自己的状态：

我这两个月越来越不焦虑了，因为很多东西越看越清楚。

这句话让我停了一下。过去两年 AI 圈的主流情绪恰恰相反——所有人都在焦虑：模型会不会又换代、投入那么大为什么效果不好、拐点到底在哪。而曾鸣是阿里巴巴集团前总参谋长、两次被 Thinkers50 评为全球最具影响力的战略思想家，他的「不焦虑」不是安慰，是一个判断：AI 刚进入第二阶段的开场，应用大爆发还没真正开始，浏览器还没有出现，所有人都在同一条起跑线上。

这场演讲被拆成六个命题（智能商业、AI 原生、产业化阶段、价值创造、创智组织、智能战略），两万多字。但对我最有冲击的只有一个论断，它藏在第一节，篇幅不长，却把我这两年一直在做、却说不清的事一句话说穿了：

真正创造巨大价值的是打开新的供给。好的私人医生、好的老师、好的理财顾问，旅游时能给你真正建议的可信的信息专家，任何一个方面我们都觉得好的供给太少、太稀缺。

不是把现有服务做得更快更便宜，是 让一批过去根本不存在的市场出现。而它之所以现在可能，是因为 AI 把满足每个人具体需求的交付成本打到了极低——低到过去只有富人和大公司买得起的东西，正在变成默认配置。

品味不是一块，是三半：其中一半正在贬值

Taste Is Not One Thing: Half of What You Call Taste Is Depreciating

 October 14, 2026  |  332 tokens  |  @HugoSkills  |  hugozhu.site

Anthropic 昨天发了一篇工程博客，讲他们怎么在五个月里把 monorepo 从 git 迁到自研的版本控制系统 Scion（合并量从 5 月的约 2500 次/天涨到 9 月的 3 万次以上，git 撑不住了）。数字都很惊人，但我停下来的是里面一句关于人的话。

他们说，参与这个项目的所有工程师，现在都认为 Claude 写代码比他们自己强。

按理说这话讲完，工程师就该没价值了。可紧接着他们写：「很多时候我们发现，工程师的作用就是告诉 Claude『no』。」

举的例子具体得扎心：迁移过程中，有好几个系统试图用「线性读 commit log」这种暴力方式去查一个变更是什么时候合进主干的，而不是去问他们的 code review 工具。能跑，结果也对——但它违反了系统的核心约束，是一个「本就不该被允许存在」的模式。还有一次，对抗性 review 对另一个内部服务过度防御，Claude 就照着加了一大堆多余的校验和复杂度。

我发现这两件事拼在一起，恰好回答了一个我最近一直在想的问题：「AI 时代品味最值钱」这句话，到底在说哪一种品味？

AI 时代的中小企业，需要一台 AI 路由器

The AI-Native Network Appliance: A Router an Agent Can Actually Operate

 October 10, 2026  |  260 tokens  |  @HugoSkills  |  hugozhu.site

前几年我在 OpenWrt 上给自己搭过一套网络：用 Tailscale + Docker + macvlan 把异地两个机房拼成一个局域网，搭 DERP relay、配 Exit Node、写策略路由，让国内流量走本地出口、海外流量走指定节点。每一次都能跑通。我还在 Tailscale 是事实上的个人弹性云基础网络 里得意地总结过这套玩法。

但有个问题一直没解决：这套网络的知识，全在我脑子里。哪条路由为什么这么走、哪个节点的密钥什么时候过期、改哪一行会把我自己的管理连接切断——没有一样写在设备上。我一旦忙别的，它就成了一个谁也不敢碰的黑盒。

一个没有网络工程师的中小公司，遇到的是同一件事的放大版：设备足够复杂，人又不够专业，网络一出故障，只能干等外援。

这篇想说的是：大模型正在改变这个前提——它把「必须有个懂网络的人」这个约束，换成了「必须有一台 AI 能安全运维的设备」。

选 Agent 项目，我第一个看的是反馈密度

Feedback Density Is the Metric That Grows Agent Engineers

 September 14, 2026  |  260 tokens  |  @HugoSkills  |  hugozhu.site

9 月初，我的数字员工「涌现」在一周里掉了三次链子。

它每天早上八点跑一轮「早读」：读公众号后台、读 GA、digest 小红书、更新 token 消耗、读 aibase——五步，预算一小时。8 月 31 日、9 月 2 日、9 月 5 日，三次吃了同一个兜底。前两次重启了事，第三次我让 opencode 做了一轮十五分钟的验尸：模型网关的机器名，被 /etc/hosts 里一行陈年映射和 DNS 搜索域联手坑了——解析结果里混进一条不通的 IPv6 路由，我常用的工具个个有回退所以毫无察觉，Agent 的运行时没有回退，当场死亡。整个排查过程我写成了 谁停掉了数字员工的早读。

事后回想，我当时的感受不是恼火，更接近于交学费的踏实。这个「早读」场景，技术上毫无炫技之处——定时任务、抓取、摘要、发消息，任何一个传统后端工程师一天就能搭完。但正是这个普通的场景，在过去几个月里每天给我生产真实的执行、真实的失败、真实的修复。我对 Agent 工程的大部分真实认知，不是从论文和 demo 里来的，是从这条 loop 里长出来的。

这让我越来越确信一个判断：Agent 应用工程师的核心竞争力，不是会不会调 Prompt、接 MCP、做 RAG，而是能不能建立一个真实的、持续运行的 Agent Loop。 而在选择做什么项目时，我会把一个指标放在非常靠前的位置：这个场景每天能给我多少次真实的执行反馈。

组织架构没变，就别谈 AI 原生

No Org Change, No AI-Native: A Structural Litmus Test

 August 24, 2026  |  230 tokens  |  @HugoSkills  |  hugozhu.site

这句话出自最近一次关于企业 AI 转型的讨论。

当时的话题是：怎么判断一家公司是不是真的 AI 原生了？很多人的第一反应是列技术清单——买了多少 AI 工具、覆盖了多少人、token 消耗增长了几倍。然后有人扔出了这么一句：

企业组织架构不变、流程不变、人才要求不变，就别谈 AI 原生。

乍一听很极端，但细想会发现它的厉害之处：它把「AI 原生」从一个技术采购问题，变成了一个组织事实问题——原生与否，不看买了什么，看结构动没动。

这个类比很精确。cloud-native 的反面不是「没用云」，而是 lift-and-shift——把单体应用原封不动搬上虚拟机，然后宣称自己上云了。今天绝大多数所谓的「AI 转型」，就是 AI 版的 lift-and-shift：把 AI 塞进旧流程、旧考核、旧管理思维里，然后管这叫原生。

前几天有人问我：Agent Builder 的终局是什么？

我没直接回答，先让他做了个实验：在 Builder 里输入一句话——「帮我创建一个采购数字员工」。

Builder 吐出来一份 YAML：

employee:
  role: 采购专员
mission:
  - 处理采购申请
context:
  - ERP
  - DingTalk
  - Supplier DB
permissions:
  - read_inventory
  - create_purchase_draft
boundaries:
  - cannot_approve_purchase
evals:
  - ...
# generated by hugo AI

我问他：你觉得这份 YAML 是什么？

他说：Agent 的配置文件。

我说：逐字段再看一遍。

他看了几秒，声音不太确定了：「这……是一份 JD？」

对。这就是这篇文章的核心判断：Agent Spec 不是软件描述，它是劳动关系的一份抽象。
