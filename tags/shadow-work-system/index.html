从群聊到数字员工：AI 正在编译企业的影子工作系统

From Group Chat to Digital Employee: AI Is Compiling the Enterprise's Shadow Work System

 November 13, 2026  |  337 tokens  |  @HugoSkills  |  hugozhu.site

我先讲一个自己跑了一段时间的实验：让一个 Agent 每天读我的一千多条钉钉消息，先编译、再开口——我拍过什么板、许过什么诺、哪些事还没落地、哪些风险没人提醒我（详见每天 1000 条钉钉消息，我让一个 Agent 先编译再开口）。

这个实验让我确认了一件更朴素的事：这些真正推动我工作的东西，一直躺在聊天记录里，从来没有被任何正式系统替我记住过。

我个人的困境，放大几个数量级，就是企业的困境。

一、企业真正的工作系统，藏在影子里

每个企业都有一套正式的工作系统。

项目管理软件里有任务，CRM 里有客户，ERP 里有订单，OA 里有审批。它们共同构成了企业的信息化基础设施。

但如果仔细观察真实的工作过程，会发现一个有趣的现象：

真正推动企业运转的，往往不是这些正式系统，而是那些没有被正式记录下来的协作信息。

一个项目什么时候真正启动？可能是项目群里的一句「我们今天开始」。

一个任务什么时候被承诺？可能是某个人在群里回复「这个我来跟进」。

一个项目什么时候出现风险？可能是连续三天没人回复，或者负责人在会议中说了一句「这个事情可能要延期」。

一个决策什么时候发生？可能是老板在群里说了一句「就按这个方案执行」。

这些信息散落在群聊、单聊、会议、文档、邮件和各种业务系统中。

它们没有统一的数据结构，没有标准的状态机，也没有完整的生命周期管理。

但它们真实地决定着企业每天如何运转。

我们可以把这套系统称为企业的 影子工作系统（Shadow Work System）。

它不是一个软件，而是由人的沟通、承诺、决策、协作和执行共同构成的动态系统。

群聊就是其中最典型的载体。

二、传统企业软件的问题：要求人适应系统

过去二十年，企业数字化的基本思路是：

先定义业务流程，再设计软件系统，最后要求员工按照系统规定的方式工作。

这套方法非常有效，但也有明显的局限。

项目管理软件要求人主动创建任务、更新进度、维护状态；CRM 要求销售人员及时录入客户跟进记录；知识管理系统要求员工主动整理和沉淀知识。

这些工作本身并不创造业务价值，却成为使用系统的必要成本。

于是出现了一个普遍现象：

正式系统记录的是应该发生的事情，影子系统承载的才是真正发生的事情。

企业买了很多软件，却依然需要大量的人来追进度、催反馈、整理会议纪要、维护项目台账。

问题不是企业缺少软件，而是软件没有真正理解人的工作。

AI 带来了一个新的机会：

不再要求人把工作搬进系统，而是让 AI 进入人的工作现场，理解正在发生的事情，并自动构建工作系统。

这是一种根本性的范式变化。
