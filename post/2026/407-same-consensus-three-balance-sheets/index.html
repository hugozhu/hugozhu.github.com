同一句「AI 壁垒在数据」，三个角度推出三个相反的行动

Same Consensus, Three Balance Sheets: Decoding AI Advice by Who Pays for It

 September 18, 2026  |  156 tokens  |  @HugoSkills  |  hugozhu.site

前几天我把手上的三份材料丢给 AI，让它整理成一篇观点汇编：一段产业对话（提问者沈X，回答者是我自己）、一场企业 AI 落地的闭门沙龙、朱啸虎在北大的演讲（Ethan 整理）。

三份材料来自三个完全不同的场合，AI 干得很利索——分门别类、提炼要点、做成对照表，最后在末尾给了我一行加粗的字：

收敛成一句话：模型能力会迅速扩散、趋同、变便宜，所以技术领先只是阶段性优势。真正的长期壁垒，都从「功能/模型」转向独占的数据、跑通的流程、沉淀的资产和用户入口。

我盯着这句看了很久，然后把它删了。

不是因为它错。它对得无可指摘。是因为 它把三份材料里唯一值钱的东西给抹掉了——那三个人说同一句话的时候，各自在指三份不同的数据，各自要把资产放进三个不同的口袋。

一、三方都同意「壁垒在数据」，但三方要的不是同一份数据

先把三份材料的原话摆出来。

来源一，产业对话里我自己的回答：大模型会吃掉纯工具型软件，因为复刻成本趋零；活下来的是有商业用户和数据的软件公司。护城河从「功能」转向「数据闭环 + 行业 know-how + 分发渠道」。

来源二，闭门沙龙的六条判断，最后一条是：长期资产是流程、Skill、评价集、上下文与权限。

来源三，朱啸虎的演讲：技术先进只是入场券，真正决定长期价值的是市场规模、规模化能力、留存、入口、商业模式和壁垒。他给的判据里最狠的一条是——最危险的处境是做成「大厂能免费集成的功能」。

三句话并排放在一起，确实指向同一个结论：模型会贬值，数据和流程会升值。AI 的收敛没有说谎。

但收敛掩盖了一件事：这三个人对「资产该沉在哪里」的答案是相反的。 下表第一列的角色是我的归类——沙龙主讲人不一定是顾问，平台方的话是我自己说的，投资人那条来自朱啸虎；但归类不影响结论，因为决定性的是各自的位置。

说这句话时他想要什么你照做之后，谁的资产负债表变好
平台方（我）你把流程、数据、协同关系沉在平台上平台：切换成本↑、留存↑、续费↑
落地顾问你把流程、Skill、评价集握在自己手里，可迁移、不锁死客户：资产在自己账上；顾问：口碑
投资人他投的是 已经有 入口和数据的人基金：标的壁垒越硬，回报越确定

注意第三行。朱啸虎说「壁垒在入口和数据」，这句话对你这个创业者是建议，对他自己是 筛选条件——他不打算帮你建入口，他打算在入口已经建成的人身上下注。同一句话，一个是行动指南，一个是准入清单。

三条建议各自都对。但你不可能同时照做：把资产沉在平台上，和把资产握在自己手里，是同一个动作的两个相反方向。

二、一个贯穿的案例：数字员工的 SPEC 到底归谁

这个冲突不是抽象的，我自己最近就在它上面做过一次真实决策。

我在 一切皆员工 里写过一套数字员工的组装方式：每个员工由一份 SPEC（岗位说明书）编译而来，配套的还有 EVAL（验收用例）、配置补丁、轨迹改进方案。当时做了一个刻意的设计选择：

员工定义全部是 框架无关的合同资产，插件全部挂在运行时旁边，而不是打进运行时里面。哪天运行时换了——转正也好、被更强的东西取代也好——迁移的是编译目标，不是员工本身。

用平台方的利益算，这个设计是「错」的。它主动降低了客户的切换成本：员工定义可以打包带走，换一个运行时重新编译就行。如果我想锁客户，正确做法是把 SPEC、EVAL 和运行时深度耦合，让它离开这个平台就读不懂、跑不了。

用客户的利益算，这个设计是「对」的。版本风险被隔离在「操作系统」那一层，制度资产不陪葬。

我当时为什么这么选？不是因为高尚，是因为一个判断：把不该锁的东西锁死，客户会提前防你；把该守的守住，客户才敢把更重的东西交给你。

而「该守的」是哪一层？我在 AI 钉钉的护城河 里写过：连接层——组织身份、权限体系、审批链、协同历史。这一层平台确实提供了别人给不了的东西，它该沉在平台上。

于是这条线就画出来了：

          客户的资产                    平台的资产
   ┌──────────────────────┐    ┌──────────────────────┐
   │ SPEC（岗位说明书）    │    │ 组织身份与权限体系    │
   │ EVAL（验收用例）      │    │ 审批链、汇报线        │
   │ 配置补丁              │    │ 协同历史              │
   │ 轨迹改进方案          │    │ 连接层基础设施        │
   └──────────┬───────────┘    └──────────┬───────────┘
              │                           │
        可打包带走                  沉在平台上
        （框架无关）                （平台独有价值）
              │                           │
              └───────────┬───────────────┘
                          │
              同一个「数字员工」，
              两份资产，两个所有者

「数字员工的资产」听起来是一个整体，拆开是两个口袋。顾问说「资产是你的」，指的是左边那一栏；我说「护城河在数据」，指的是右边那一栏。两句都对，但它们不是同一句话。

这才是那三份材料真正的内容。AI 的收敛把它们合成一句，等于把两个口袋缝成了一个。

三、解码工具：三问

把上面的观察压成一个可操作的工具。下次听到任何 AI 时代的建议——尤其是那种听起来无懈可击的共识——问三个问题：

第一问：说这句话的人，钱从哪来？ 平台方靠续费和切换成本，顾问靠项目费和口碑，投资人靠标的的壁垒和退出。三个收入结构，会推出三个都自洽但方向相反的建议。

第二问：如果他的建议是对的，谁的资产负债表会变好？ 这是最锋利的一问。「把流程沉淀成资产」——沉在谁的账上？「壁垒在数据」——谁握着这份数据？「先建平台再找场景是错的」——那谁该建平台？答案不同，建议的性质就完全不同。

第三问：他有没有主动说出对自己不利的部分？ 前两问是查利益，这一问是查诚实，而且最难伪造。

朱啸虎那条「最危险是做成大厂能免费集成的功能」，恰恰是 对 VC 自己的约束——他的收入来自标的的长期价值，而这条判据等于当众宣布：一批功能型 AI 公司不值钱。说这话的人，亲手压低了市场上相当一部分项目的估值，其中可能就有他自己的在投标的。一个人主动说出对自己不利的判断，可信度立刻不一样。

反过来，我自己说「护城河在数据闭环」的时候，如果不同时说「但客户的员工定义应该可迁移、我们主动降低了切换成本」，那就是只说对自己有利的一半。第二节的自我披露不是修辞姿态，是第三问对我自己的要求。

四、我站在哪一边

写到这里必须交底：我是三方里的平台方。 这篇文章本身也有立场——它教你对平台方的建议保持警惕，包括我的。

按第三问的标准，我该说清楚自己的利益结构：

  • 我希望你沉在平台上的：组织关系、权限体系、协同历史。这一层是平台的真实价值，也是别人短期给不了的。
  • 我不该希望你锁死在我这里的：你的员工定义、你的评价集、你的流程知识。这些是你业务的 know-how，把它们做成只在我平台上能读懂的格式，是拿你的资产给我的留存指标垫背。

区分这两者，是我给自己划的线。划这条线不是道德选择，是长期账：靠锁死换来的留存，会在客户发现的那一天连本带息还回去。

五、AI 为什么爱做收敛，而收敛为什么危险

最后回到开头那个动作。AI 把那三份材料收敛成一句话，这件事本身就是这篇文章最好的论据。

模型的目标函数是 连贯，不是 正确。三个立场冲突的来源，压成一句人人点头的共识，在「连贯」这个指标上是满分——读起来顺、没有矛盾、可以直接引用。而在「正确」这个指标上，它丢掉了唯一有决策价值的信息。

这个机制我在 历史是极好的律师，极差的法官 里写过一次：叙事会把混沌压缩成必然，把侥幸压缩成智慧，而 流畅度恰恰是危险信号。同一个机制，那次作用在历史类比上，这次作用在多来源整理上。

所以一份合格的多来源整理，不该以「收敛成一句话」结尾，该以 冲突清单 结尾：

  • 三个来源分别是谁，各自的收入结构是什么
  • 他们在哪一句上看起来一致
  • 这句话在三个立场上分别指向什么行动
  • 哪些行动互斥，互斥的部分该由谁来裁决

裁决的人只能是你。因为只有你要承担后果——这一点又回到了 判断力会成为新的健身：AI 没有代价，它不会为选错边心疼，所以它的收敛在结构上就不含判断。

「AI 时代壁垒在数据」——这句话你可以留着，它是对的。但下次听到它，先别点头，先问一句：谁的数据？

你的组织里，哪些资产该沉在平台上、哪些该握在自己手里？这条线你亲手画过吗，还是默认接受了某一方的版本？欢迎留言聊聊。
