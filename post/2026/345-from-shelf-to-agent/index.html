从货架到 Agent：平台争夺的不再是人

From Shelves to Agents: Platforms Compete for Intent, Not Users

 Posted on August 13, 2026  |  2 min  |  275 words  |  @HugoSkills

上周的战略会上，有人问了我一个问题：如果 Agent 真的能替人完成工作，那工作软件公司以后卖什么？

这个问题听着抽象，我换个问法：货架电商时代，平台卖的是货架和流量——商家买排名，用户搜索、比价、下单。那当 Agent 替人买东西的时候，平台卖什么？

电商其实已经在回答这个问题了，因为它正在路上。而我把电商这二十年的演进，和工作软件的演进摆在一起看，发现它们在走同一条曲线。

先说结论： 过去平台争夺的是「人」；AI 时代平台争夺的是「人的意图」和「Agent 的行动」。

一、先看电商：它已经走完两次范式迁移

电商这二十年，明明白白经历了三个阶段：

  • 货架电商：人搜索、浏览、购买。平台的护城河是 SKU 加流量，增长靠拉用户、拉商家、扩 SKU。核心逻辑是「我自己找、我自己买」。
  • 内容电商：推荐、Feed、直播、种草。系统开始替你发现——你本来没想买，刷着刷着就买了。护城河变成注意力、内容和算法，增长靠时长和转化率。
  • 意图电商（正在发生）：Agent 理解需求，直接完成购买。人只说目标，系统替你完成。护城河正在变成用户意图、交易数据和信任。

注意每次迁移，争夺的对象都换了一层： 流量 → 注意力 → 意图。 平台没有变，变的是它截获的东西。

二、工作软件，走在同一条曲线上

把电商当参照系，工作软件的轨迹一目了然。下面这张表，左边是电商，但只是脚手架——右边那一列，才是论点：

看第三行。工作软件在 Agent 时代的护城河，是五个要素：Identity、Context、Permission、Action、Feedback。我在 数字员工背后的 Agent，是五层基础设施的叠加 里拆过这五层——身份、上下文、边界、验收、学习，全部由组织提供，模型厂商提供不了。这不是巧合：表格推到 Agent 那一行，推出来的就是组织本身。

再看第四行的终局判断：谁拥有最完整的上下文，谁拥有最强的执行权。这正是 AI 的竞争变了：未来是上下文的竞争 那个判断的管理层版本——上下文竞争不是一个技术观点，是一张商业地图。

三、四条迁移，和一个换轨的公式

把整张表压缩，最值得记住的是这四行迁移：

流量 → 工作入口 → Context
商品 → 功能 → Agent
搜索/点击 → 推荐/协作 → 意图/任务
人买东西 → 人使用软件 → Agent 替人行动

对管理层来说，最有用的推论藏在增长公式里。传统 SaaS 的增长公式是：

更多用户 × 更多 Seat × 更多功能

Agent 时代会变成：

更多任务 × 更多 Agent × 更多执行

这不是文字游戏——它直接改变 KPI 和资源分配。判断一家公司站在哪个时代，看它考核什么就够了：

def paradigm_position(company) -> str:
    """判断一家公司站在迁移曲线的哪一段：看它用什么公式考核增长。"""
    if company.kpi.startswith("seat"):
        return "① 货架时代：还在按人头卖软件"
    if company.kpi.startswith("usage"):
        return "② 协作时代：卖使用时长和范围"
    return "③ Agent 时代：卖 Agent 完成的任务量"

四、最重要的战略变化，不是「给 SaaS 加 Copilot」

顺着公式换轨，战略上的分水岭就清楚了。

大多数公司现在做的事是： 「给 SaaS 加一个 AI Copilot。」 在原有产品里嵌一个助手，功能不变，界面不变，计费不变。这是把范式迁移当成了一次功能升级。

但表格里推出来的方向是另一件事： 「把工作软件从人操作的软件，变成 Agent 工作的基础设施。」

这两句话的区别，是装修和换地基的区别。前者的主语还是人，后者的主语已经是 Agent。

这也是为什么在这个阶段，组织、身份、权限、IM、文档、审批、工作流、连接器、反馈/Eval——这些过去分散在各处的能力——会重新组合成一个新的护城河：

软件不再只是记录工作，而是理解工作、执行工作、学习工作。

我在 数字员工是下一个十年的故事 里说过，Agent 改变软件，数字员工改变组织。这张表把那句话又往前推了一步：当工作主体从人变成 Agent，「组织」这个词在软件里的含义也变了——它不再是一套给人用的管理功能，而是一套给 Agent 用的执行环境。

五、最强的反方会说什么

写到这儿，必须替最挑剔的读者把反驳说出来： 这个类比成立吗？

电商的商品是标准化的，决策快、信任成本低，Agent 替你买一件纸巾没什么心理负担。但工作是异构的、决策链长、信任门槛高——把发工资、签合同、批预算交给 Agent，和让它买纸巾是一回事吗？拿电商套工作软件，是不是刻舟求剑？

这个反驳是对的——如果类比的对象是商品，那确实刻舟求剑。但类比对齐的不是对象，是 范式结构：平台价值从「服务人的操作」迁移到「代理人行动」，这个方向和对象无关。

而且更关键的是反过来说： 正因为工作的信任门槛高，护城河才更深。 Agent 替人干活需要的 Identity、Context、Permission、Feedback，全部长在组织自己的系统里——通讯录、审批流、权限体系、决策历史，外部模型一个 token 都拿不到。电商里 Agent 替你买，信任建立在平台的交易记录上；工作里 Agent 替你干，信任建立在组织的上下文上。前者别人还能复制，后者复制不了。

所以信任门槛不是这条路的障碍，是这条路的壁垒。至于怎么验证自己手里有多少这样的壁垒——用 用 1% 法则，给你的公司做一次 AI 盘点 里的方法，盘一遍哪些任务的执行权是因为「拿不到你的数据」而永远留在你手里的。那就是你的 Agent 执行量起点。

写在最后

如果只留一句话给管理层，我会放这一句：

货架电商之后是「Agent 替你买」；SaaS 之后是「Agent 替你干」。两者的共同终局：从争夺流量，走向争夺 Context；从服务人的操作，走向代理人的行动。
